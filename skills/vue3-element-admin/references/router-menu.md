# 路由与菜单

处理静态路由、后端动态菜单或路由 Meta 时读取本文。先检查 `src/router/`、`src/api/system/menu/types.ts` 和相邻路由，不从示例推断当前类型。

## 选择配置入口

- 登录、错误页、首页等固定入口放在 `src/router/index.ts` 的静态路由中。
- 业务菜单优先通过后端菜单管理配置，前端不重复声明。
- 父子层级、隐藏规则和重定向应沿用相邻路由，避免同时在前后端维护同一菜单。

## 静态路由示例

```typescript
{
  path: "/system/user",
  component: Layout,
  children: [
    {
      path: "",
      name: "User",
      component: () => import("@/views/system/user/index.vue"),
      meta: {
        title: "user",
        icon: "user",
        keepAlive: true,
      },
    },
  ],
}
```

- `name` 保持唯一、稳定；修改前搜索缓存、权限和导航代码是否依赖它。
- 子路由 `path` 通常不以 `/` 开头；顶层路径按现有结构处理。
- `meta.title` 优先使用语言包 `route` 命名空间中的 key；允许既有路由使用直接文案作为回退。
- 路由组件使用动态导入，不在路由文件中提前加载业务页面。

## 常用 Meta

| 字段          | 用途                              |
| ------------- | --------------------------------- |
| `title`       | 菜单、标签和面包屑标题或 i18n key |
| `icon`        | 菜单图标                          |
| `hidden`      | 从菜单中隐藏                      |
| `keepAlive`   | 加入标签页缓存                    |
| `affix`       | 固定在标签栏                      |
| `roles`       | 静态路由的角色限制                |
| `params`      | 路由附加参数                      |
| `externalUrl` | 外链地址                          |

实际可用字段和类型以当前路由声明及菜单 API 类型为准。

## 动态菜单

后端返回的 `component` 是相对 `src/views/` 的路径，例如 `system/user/index`。动态路由转换代码使用 `import.meta.glob` 匹配页面文件，并将顶层 `Layout` 标识转换为布局组件。

新增动态菜单时核对：

- 路由路径、名称和组件相对路径能够唯一匹配。
- 菜单类型、父级、排序、显示状态和重定向符合后端模型。
- 权限标识与页面按钮、接口鉴权保持一致。
- 开启缓存时同时验证标签页切换和刷新行为。
- 标题 key 已存在于所有受支持语言包，或明确接受原文回退。

不要因为新增动态菜单而修改静态路由，除非该入口必须在获取后端菜单之前可访问。
