# 国际化

## 路由标题

`translateRouteTitle(title)` 会查找 `route.${title}`；存在对应 key 时返回翻译，否则返回原始标题。因此新菜单标题优先使用稳定 key，既有直接文案可以正常回退。

```typescript
export function translateRouteTitle(title: string): string {
  const key = `route.${title}`;
  return i18n.global.te(key) ? i18n.global.t(key) : title;
}
```

新增 key 时同步修改所有受支持语言文件，例如：

```json
{
  "route": {
    "user": "用户管理",
    "role": "角色管理"
  }
}
```

对应英文文件必须使用相同 key。不要只修改当前语言，造成切换后显示 key 或旧文案。

## 页面文案

模板中使用 `$t`，脚本中使用 `useI18n()`：

```vue
<template>
  <span>{{ $t("navbar.search") }}</span>
</template>

<script setup lang="ts">
import { useI18n } from "vue-i18n";

const { t } = useI18n();
const title = computed(() => t("login.username"));
</script>
```

- 是否国际化普通业务页面取决于现有模块和用户范围；不要擅自扩大为全站翻译。
- key 按当前命名空间组织，先复用已有 key。
- 需要响应语言切换的派生文本使用 `computed`，不要在初始化时固化翻译结果。
- Element Plus 的语言跟随应用语言状态；新增语言时还要提供对应组件库 locale。
