# 认证、授权与安全

## 认证边界

- 默认保护需要登录的业务路由；公开路由使用明确的 `@Public()` 或项目等价机制标记。
- JWT payload 保持最小且有类型，常见字段为 `sub`、会话或令牌版本、必要的租户上下文。不要把大量可变权限塞入长生命周期令牌。
- 校验签发方、受众、过期时间和算法；密钥来自运行时配置并支持轮换。
- 刷新令牌应可撤销，服务端只存摘要或受保护的会话记录；轮换时处理重复使用和并发刷新。
- 登出和密码变更是否立即使旧令牌失效，应由令牌版本、黑名单或会话存储明确实现。

生产环境的 Session 使用外部 store，并根据部署方式设置 `httpOnly`、`secure`、`sameSite`、过期时间和代理信任。不要依赖单进程内存 Session。

## 授权与数据范围

- 认证回答“是谁”，权限守卫回答“能否执行动作”，数据范围回答“能操作哪些记录”；不要把三者混在一个布尔判断中。
- 权限标识沿用现有词汇。例如项目选择 `sys:user:create/update/delete` 后，不在相邻接口混用 `add/edit`。
- Guard 没有发现权限元数据时是默认允许还是默认拒绝，必须结合公开路由机制显式决定，并为该默认行为测试。
- 对资源的所有权、部门范围或租户范围在服务端查询中强制执行，不能信任客户端传来的 ownerId、deptId 或 tenantId。
- 超级管理员绕过规则应集中、可审计且有测试，不能散落在 Controller。
- 通用权限组件通过窄接口或 injection token 获取所需数据，避免 `common` 直接依赖具体业务模块。

## 密码、验证码和临时凭证

- 使用成熟的密码哈希算法与合理 cost；比较时使用库提供的安全函数。
- 密码哈希永不出现在 Entity 响应、日志、错误详情或序列化缓存中。
- 验证码答案不返回客户端。客户端只得到挑战 ID、图片或完成挑战所需的非答案数据。
- 短信和邮件验证码有短有效期、尝试次数限制、发送频率限制和一次性消费语义。
- 固定验证码只能存在于明确隔离的开发测试适配器中；生产配置检测到该模式时启动失败。

## 文件安全

- 校验大小、允许的 MIME、扩展名和实际文件签名；不要只信任客户端文件名或 Content-Type。
- 生成服务端文件名，将原始文件名仅作为经过清洗的展示元数据。
- 本地存储的读取和删除先 `resolve` 路径，再确认目标位于允许的存储根目录内，防止 `../` 和绝对路径逃逸。
- 对象存储 key 使用受控前缀；删除操作校验资源归属和权限。
- 下载响应设置安全的 Content-Disposition 和内容类型；对主动内容考虑独立域名或强制附件下载。

## 配置和部署

- 提交 `.env.example` 而不提交真实 `.env`；密钥由部署环境、secret manager 或编排平台注入。
- Docker build context 用 `.dockerignore` 排除 `.env`、测试输出和本地凭据，镜像中不复制秘密。
- 使用锁文件的冻结安装，生产镜像仅包含运行时依赖，并尽可能使用非 root 用户。
- 启动时校验关键配置的存在、类型和范围；不要等到首个请求才发现密钥缺失。
- CORS 使用来源 allow-list；需要 Cookie 时不能使用通配来源。
- 限流只保留一个清晰的主机制，避免 Middleware 与 Guard 重复计数。登录、验证码、重置密码和上传使用更严格策略。

## 错误与日志

- 未知异常对外返回通用消息，对内记录结构化上下文和 request ID。
- 日志脱敏 Authorization、Cookie、密码、验证码、令牌、身份证件和其他隐私字段。
- 认证失败不泄露“账号存在但密码错误”等可枚举信息，管理审计日志可以保留更精确的内部原因。
- 不把原始数据库错误、上游响应、堆栈或本地绝对路径直接返回客户端。
- 安全相关状态变更记录操作者、目标、动作、结果和时间，但不记录秘密本身。

## 安全测试重点

- 未登录、令牌过期、令牌撤销和刷新令牌重放。
- 普通用户访问管理员动作。
- 横向越权访问其他用户、部门或租户的数据。
- 批量接口绕过单条权限判断。
- 非法上传、路径穿越和越权删除。
- 严格 CORS、Cookie 属性、限流和错误信息泄露。
