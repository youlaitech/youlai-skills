# 文风

起草和润色正文时读。目标是读起来像有经验的工程师在讲自己做过的事，不是像文档。

## 标题

弱和强是同一个主题的两种写法，比的是表达，不是主题大小：

| 弱 | 强 |
|---|---|
| Spring Boot 多租户方案浅析 | Spring Boot 多租户：数据隔离在哪一层做 |
| 一次 ThinkPHP 架构升级实践 | ThinkPHP 8 升级：破坏性变更、迁移步骤与回滚 |
| 关于动态路由的一些总结 | 动态路由：无权限页面为什么不进路由表 |
| 聊聊 JWT 会话管理 | JWT 会话管理：主动失效为什么要多存一份状态 |

规律：弱标题用一个空泛动词占位（浅析、深入理解、总结、聊聊），强标题把对象和具体问题说清楚。标题里的数字和结论必须有正文支撑。

## 章节标题

H2 是章节主题，H3 是这章下的子主题，最多三层。

同级标题保持相近的句式：都是动宾（配置动态路由 / 验证数据范围）、都是陈述（数据隔离在服务层完成）、或都是名词短语。句式一致是软要求，别为了让句式或字数整齐，改坏一个本来清楚的标题。

标题要能独立表达信息。"背景""实现""注意事项""其他"这类，读者看完不知道里面有什么。

写完做一次目录测试：只看 H2 列表，能不能复述出文章主线。能，目录就成立了。

各类文章的完整目录见 [article-types.md](article-types.md)。

默认用章节编号：H2 写「一、环境准备」，该章下的 H3 写「1.1 服务器基础环境」。实战教程步骤多，正文常要靠"见 2.2 节"定位，编号能省掉冗长的章节名指代，读者也能记住自己读到哪。只有两三个小节的短文、或纯观点文，可以不加，标题直接写内容。

## 前言

读者在一屏内决定要不要继续看。前言要让人马上认出"这说的是我的问题"。

**先给结论**

> 隐藏菜单不等于权限控制。前端拿到的菜单只影响显示，接口能不能调、能取多少数据全在后端判断。下面按一次请求的链路，看每层实际拦得住什么。

**先给场景**

> 生产环境报 `Token 已过期`，但用户登录还不到十分钟。排查下来是 Redis 和 JWT 各算各的过期时间，刷新逻辑只更新了其中一个。

三种开头直接重写：

- "随着……的快速发展"——换成任何主题都成立
- "本文将从 A、B、C 三方面介绍"——把目录搬到前言
- "这个方案我们打磨了很久"——读者关心结果，不关心投入

## 段落

一段一个意思。结论或主题句放最前面，后面跟原因和例子。**主题句超过两行就失效**：扫读的人只看每段第一句，太长就抓不到要点。

**同一意思写两遍是段落里最重的 AI 味**：

> 权限校验非常重要。在实际开发中，做好权限校验可以有效防止越权访问，提升系统安全性。因此我们需要重视权限校验。

> 改成：权限校验必须放在后端。前端能拦住入口，拦不住直接调接口的人。

段落长短要变。连续几段都是三句话，读起来像模板；一句结论单独成段反而醒目。

拆长段落时从语义边界切，让每段都有自己的结论句。从句子中间断开，读者得连读两段才拼出一个意思。

## 讲原理

首次出现的缩写给一句解释，之后直接用。术语、类名、配置项保持官方拼写。

不熟悉的机制从读者已知的东西切进去：

> 静态路由像提前印好的门牌表，打包时就登记完；动态路由是登录后才登记你有权访问的那几扇门。

比喻只负责建立直觉，之后必须补真实机制（路由注册、权限数据来源）。只给比喻不给机制，等于没讲。

只讲读者要做的动作和会卡住的地方。磁盘格式、内核权限检查、`chmod 755` 和 `777` 的差别，这些是作者觉得有意思，不是读者会卡住的地方。

## 代码

注释写原因和约束，不复述代码动作：

```java
// 差：判断 token 是否过期
// 好：redis 与 jwt 各自过期，这里以 redis 为准，避免 key 已删还能通过校验
```

命令行注释同理，只说命令看不出来的前提和原因：

```bash
# 差：旧目录整体复制为新目录：-a 保留权限与时间戳
cp -a /data/minio /data/rustfs

# 好：-a 保留属主和权限
cp -a /data/minio /data/rustfs
```

代码块前说目的，代码后说结果或关键观察。连着贴几段代码不说一句，读者不知道要看哪。展示错误写法和正确写法时，一并说明区别会造成什么后果。

## 图

截图截到与结论相关的区域，去掉浏览器标签、桌面和无关窗口。一张图只标 1 至 3 个重点，标多了等于没标。图片在手机宽度下要能看清标注文字，看不清就重新截或改画图。

图片粘贴后，如果 alt 是编辑器默认的"在这里插入图片描述"，改成一句话说明图里是什么。

需要截图但手头没有时，在该放图的位置留 HTML 注释，写清拍什么、从哪进、要让读者看到什么。注释不进正文，就算漏删也不会被读者看到：

```markdown
<!-- 图：RustFS 控制台首页——浏览器打开 http://服务器IP:9001，用 AK/SK 登录后的桶列表页 -->
```

截图后直接在注释的位置粘贴，再把注释删掉。发布前搜一遍 `<!--`，确认没有遗留的草稿标记。

## 这些写法别用

| 类型 | 例子 | 问题 |
|------|------|------|
| 生造词 | "部署心智模型"、"和 aliyun 对仗" | 读者看不懂，直接说"部署方式不同" |
| 抒情 | "这是停更砸到你身上的第一块石头"、"还在带病运行" | 技术文里假 |
| 写作自述 | "本文的引子"、"先给结论表"、"先看事实，再谈迁移" | 读者不关心你怎么写的 |
| 升华 | "真正值钱的不是 X 而是 Y"、"比任何一家公司都活得久" | 观点说一次就够，说第二遍是灌水 |
| 自证 | 为一句结论挂 issue 编号和参考文章 | 有出处给一次就够，不用堆 |
| 加粗滥用 | 一段加粗三处以上 | 全是重点等于没有重点 |
| 英文堆叠 | 一句话连排三个以上英文术语 | 读者要逐词翻译，读起来卡 |

表格讲完再用散文讲一遍，是重复最集中的地方：一张清单列全了，就不必在后面逐条展开。

## 排版

- 一段一个意思，段间空行，不用换行符硬断句。
- 中英文、中文与数字之间按写作习惯留空格，全文统一即可。
- 中文用全角标点，代码和命令用半角。
- **标点别抢戏**：引号、省略号全文统一；破折号一段最多一个，连着用像翻译腔，也是 AI 文本最明显的特征。
- 代码块标注语言，长代码节选并注明来源文件。
- 表格四五列以上在手机上要横向滚动，面向手机发布时拆表或改成列表。
- 一个 H1，标题层级不跳级，不用加粗伪装层级。

排版细节不必逐条纠结，通读顺畅比严格执行某一条更重要。
