# 表达与讲解

用于正文起草与润色。目录选择和标题层级见 [article-types.md](article-types.md)。

## 标题开头

标题点明技术对象和核心任务或问题，与正文范围一致。实战写清要完成什么，原理写清要解释什么，例如“Spring Boot 接入 Redis：缓存商品查询”“Go HTTP 客户端的请求流程”。核心信息前置，不罗列子功能，不用“最全、彻底掌握”等夸大承诺。

开头直接交代场景、成果或关键判断，以及必要前提。已有成品图、演示或运行结果时，选最能说明目标的一项展示，不从行业趋势或技术的全部优势讲起。

## 内容推进

用同一案例或分析对象贯穿主线，名称、字段和代码前后一致。每节解决明确的问题；有依赖时交代承接关系，不为衔接复述上一节，也不写只宣布“接下来详细介绍”的空话。

关键设计说明约束、选择和后果。封装组件或工具时，先展示期望用法，再解释内部职责；只有实际存在取舍时才比较方案，不给简单实现制造假困难。

新增模块说明输入、输出及其职责。分阶段实现时，讲清在已有能力上增加了什么，再沿同一操作或调用检查结果，避免只按文件顺序浏览代码。

必要的新概念在首次使用时讲清。用具体输入、过程或反例支持机制和结论，保留必要推导，不把文章压成操作清单或知识点堆积。

## 代码呈现

文件或模块首次出现时交代用途、位置和接入关系；后续片段只说明新增行为与关键理由，不重复上下文，不逐行翻译语句。

独立示例给最小完整实现、必要依赖和执行方法；已有项目说明起点与改动位置。长实现节选关键路径并给完整代码入口，不为凑短删掉决定正确性的逻辑。

可复制代码不夹带行号、增删前缀或拼接用省略号。完整示例含必要导入和定义，节选说明已有对象与省略范围，伪代码明确标注；补丁用 `diff` 标注，不冒充完整文件。

命令与输出分块，代码块标注实际语言。保留理解和执行所需的参数，输出只节选有关部分，并保留判断结果的依据。代码以文本提供，截图用于界面效果或运行状态。

## 结果验证

关键里程碑说明输入、操作和应观察到的行为，简单步骤一句带过，不机械重复验证小节。

用关键断言或可观察的结果证明文章承诺，不能以服务启动、接口返回成功代替完整功能验证。覆盖正常流程与会改变结果的关键分支，不扩成无关的测试清单；执行情况按技术核验要求表述。

## 语言表达

用平实、准确的语言，有判断也有原因。一段集中讲一件事，保留因果关系，避免满屏孤立短句和清单。

把“提高效率、更加灵活”等笼统评价换成具体变化及其原因。例子和比喻要回到真实技术行为，不能代替论证。

## 图文规范

段落承载解释，列表承载步骤或并列项，表格承载比较与检索，图承载流程、关系或操作效果。信息简单时直接说明，不为形式配图。

同组图统一配色语义、字体层级、形状和箭头含义，对象名称与正文、代码一致，不只靠颜色区分。需要跨段引用时给图号与短图注，说明图支持的关系或结论。

按实际阅读宽度保证文字可辨、连线可追踪；复杂大图拆分，不靠缩小字号塞满内容。尺寸和工具按交付场景选择。

代码符号、命令、路径和配置项用行内代码，技术名称按官方拼写，中英文与数字间距统一。代码和引用保留原有语法，加粗只强调关键信息。

## 删除冗余

删除换个技术名仍成立的空泛背景、重复优势、无依据的赞美、作者投入自述、目录式前言和重复正文的总结。相同信息只在最合适的位置解释，引用时不整段重述。

以是否帮助理解、操作、选择或验证决定去留；必要定义、推导和提醒不删，不设固定字数、段落行数或代码行数。主线结束即可收尾，不强凑总结。

## 参考博文

按题材借鉴目录、正文与示例如何推进主线。以下目录保留原文措辞；技术实现按目标版本另行核对。

### 短篇功能

[冴羽《从零实现一个 VuePress 插件》](https://github.com/mqyqingfeng/Blog/issues/250)。适合范围集中的插件、工具开发文章。

原文同级主体目录，省略“前言”和“系列文章”：

```text
本地开发
初始化项目
插件设计
插件开发
插件选项
代码参考
```

单层短标题交代开发顺序，围绕代码复制插件说明文件位置和接入方法，再扩展选项，最后提供完整源码。原文基于 VuePress 1、Vue 2。

### 原理解析

[Draven《Go 语言 HTTP 标准库的实现原理》](https://draven.co/golang/docs/part4-advanced/ch09-stdlib/golang-net-http/)。适合参考原理长文如何用两层目录划清职责。

原文主体 H2 为“设计原理、客户端、服务器、总结”。下面节选客户端与服务器的原文层级，省略章节编号：

```text
客户端
  构建请求
  开启事务
  等待请求
服务器
  注册处理器
  处理请求
```

父节表达分析对象，子节表达处理过程；先建立协议与模块关系，再沿调用流程解释源码，配图和源码链接支持具体解释。源码分析应核对目标 Go 版本，不把旧实现当成当前行为。
